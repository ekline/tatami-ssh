# Workspace decisions

Protocol and architecture decisions (C-xx, P-xx, AQ-xx, D-xxx) are recorded in
`tatami-ssh-design-state-checkpoint.md` §1 and are not duplicated here. This
file records decisions about the Cargo workspace itself. Dates are the date the
decision was recorded.

| ID | Date | Decision | Rationale / consequence |
|---|---|---|---|
| W-01 | 2026-09-20 | All seven package boundaries exist from the start as documentation-only scaffolds. | Supersedes the checkpoint §2 suggestion to create packages lazily. Lets dependency direction and feature policy be verified mechanically before code lands. Each package still gains functionality only when its first real slice is implemented. |
| W-02 | 2026-09-20 | Every library is `#![no_std]`; `std` is a feature only on `tatami_ssh_tcp`, `tatami_ssh_quic` and `tatami_ssh`. | Keeps the `std` prelude out of portable modules even in host builds. See `architecture.md` portability layers. |
| W-03 | 2026-09-20 | `tatami_ssh_wire/alloc` is the only opt-in feature among the shared protocol packages; `keys`, `auth` and `connection` require `alloc` unconditionally. | Bounded, allocation-free codecs are a real embedded need; allocation-free state machines are not a current requirement and would complicate the API. |
| W-04 | 2026-09-20 | The facade's `std` forwards to bindings via weak features (`tatami_ssh_tcp?/std`) and never selects a transport. | `std` alone compiles only the facade host modules. Transport selection is always explicit. |
| W-05 | 2026-09-20 | Client and server are modules of `tatami_ssh`, not separate crates. | Library reuse is met by public modules; a split is deferred until dependency weight or release cadence justifies it. |
| W-06 | 2026-09-20 | No common `Transport` trait, KEX abstraction, or `tatami-crypto` crate. | Matches C-07 and checkpoint §2.1. Sharing engine-driving code between bindings is a later, evidence-based refactor. |
| W-07 | 2026-09-20 | MSRV 1.85, edition 2024, resolver 3; CI checks 1.85.0 and stable; no `rust-toolchain` file. | Edition 2024 is the first available on 1.85. Contributors keep their default compiler. |
| W-08 | 2026-09-20 | `Cargo.lock` is committed; `publish = false` on every package. | Reproducible CI and application builds without committing to an API surface. |
| W-09 | 2026-09-20 | Core/alloc-only verification uses `thumbv7em-none-eabi`; it is required in CI and optional locally. | A host check cannot detect transitive `std` use because `std` is always present on the host. |
| W-10 | 2026-09-20 (extended) | Tests and future interoperability harnesses live inside Cargo packages. Fuzz harnesses are real, isolated Cargo packages under `fuzz/` with their own workspaces and lockfiles, excluded from the production workspace. | A virtual workspace root is not a test package; root-level test directories would create apparent coverage with no executable harness. Isolation keeps nightly-only flags and harness dependencies (`libfuzzer-sys`, `arbitrary`, `serde_json`) out of the production graph. |
| W-11 | 2026-09-20 | The first diagnostic client is an *initial-offer probe* that sends only a client identification and never a client `KEXINIT`. | Tatami has no implemented algorithm set; advertising copied, empty or placeholder lists would be a false claim on the wire. Servers that wait for the client's proposal yield a documented partial result at the deadline. |
| W-12 | 2026-09-20 (revised) | Identification **content** syntax (`SSH-proto-software [comments]`: prefix, separators, token rules, CR/LF/NUL rejection, borrowed fields, content encoder) lives in `tatami_ssh_wire::ident` and is shared by all bindings. Identification **exchange framing** (terminator scanning, fragmented reads, server prelude lines, the 255-byte line limit measured with the observed terminator, LF-only acceptance) and the supported-version policy (`2.0`/`1.99`) stay in `tatami_ssh_tcp::ident`. Initial packet framing stays in `tatami_ssh_tcp`. | The content is what both TCP and the proposed QUIC binding must carry (the exchange hash and the QUIC session binding both need exact content bytes); the framing is not. The shared parser authorises no protocol version and imposes no length limit; QUIC must define its own record limits and placement later. Original W-12 kept everything in `tatami_ssh_tcp`. |
| W-13 | 2026-09-20 | `tatami_ssh_wire` message decoders are syntactic; recognition of `KEXINIT` marker names (`ext-info-*`, `kex-strict-*`) is a separate annotation function. | Keeps unknown names intact and prevents a report helper from becoming an accidental negotiation policy. |
| W-14 | 2026-09-20 | The probe adapter is blocking `std::net` with per-phase deadlines; no async runtime is chosen. | A runtime commitment is not needed for the probe and would leak into `io` before a provider audit. Synchronous name resolution is outside the deadlines and documented as such. |
| W-15 | 2026-09-20 | `OpeningEngine` never reuses a local channel number; cancelled numbers are tombstoned (bounded) to classify late replies. | RFC 4254 cannot withdraw an `OPEN`. Reuse must wait for a close lifecycle that defines when the peer can no longer reference a number; deferring reuse avoids ambiguity without inventing a wire extension. |
| W-16 | 2026-09-20 (revised) | Process exit statuses are about the *process*, never about an individual peer. `tatami-client`: 0 complete observation, 1 incomplete or network/protocol failure, 2 usage. `tatami-server observe`: 0 clean finite or requested stop, 1 listener/output/runtime failure (bind, accept, sink write), 2 usage or unsupported command. A malformed or timed-out peer is a `connection_observation` record, not a failure status. | Stable statuses for scripting; an observation run must not fail because one client misbehaved. Supersedes the first-round stub rule "server exits 1 for any invocation". |
| W-17 | 2026-09-20 | Packet-length cap defaults to 64 KiB (configurable), above the RFC 4253 §6.1 35 000-byte mandatory baseline. | The baseline is a floor implementations must accept, not a maximum. The cap is local policy and is enforced from the header before the body is buffered. |
| W-18 | 2026-09-20 | The server-side observer sends only a server identification (`SSH-2.0-tatami_observer_0.1.0`), never a server `KEXINIT`, host key or disconnect packet. | Mirror of W-11: no implemented algorithms means nothing honest to advertise. The observer is a diagnostic, not an SSH service, and its help text says so. |
| W-19 | 2026-09-20 | Client bytes that do not begin an `SSH-` identification end the observation as `unexpected_input` with a bounded sample (256 bytes). The client probe keeps its server-prelude support. | RFC 4253 §4.2 allows prelude lines from the server only. Treating client junk as a prelude would misclassify non-SSH traffic. |
| W-20 | 2026-09-20 | Shared pre-`KEXINIT` handling lives in `tatami_ssh_tcp::initial` (bounded `InputBuffer`, `InitialPackets`, `InitialError`); probe and observer are thin role-specific state machines over it. Both reject over-capacity input before copying. | Removes the first round's caller-drained unbounded feed. No common transport trait was introduced. |
| W-21 | 2026-09-20 | Listener: blocking sockets, one detached worker thread per admitted connection, capacity acquired before spawn, non-blocking accept polled every 25 ms, excess connections accepted and closed without a banner and counted. No async runtime. | Bounded concurrency without a runtime choice; a stop never depends on another client connecting. Defaults (127.0.0.1:2222, 32 concurrent, 5 s per connection, 128 pending records, 5 s shutdown grace) are local policy. |
| W-22 | 2026-09-20 | Records go through a bounded channel to a single sink thread. Workers `try_send` and count drops; a failing sink stops the run; a blocked sink is abandoned after the grace period. Records over 256 KiB are re-emitted truncated (`record_truncated: true`). | A wedged stdout must never hold peer sockets open or grow memory. Drop counts are reported in the final summary rather than hidden. |
| W-23 | 2026-09-20 | JSON Lines are produced by `tatami_ssh::json`, a small RFC 8259 serializer; raw bytes appear as lossy UTF-8 text plus bounded `_hex`. `serde_json` is a dev-dependency only, used by tests as an independent parser. | `tatami_ssh::text::quoted` emits `\xNN`, which is not JSON. A proper serializer with an independent parser in tests keeps records machine-readable without adding a runtime dependency to any library. |
| W-24 | 2026-09-20 | Lint policy: Clippy's default set with `-D warnings` on `--no-default-features` and `--all-features`, plus `#![warn(missing_docs)]` and `#![forbid(unsafe_code)]` in every library. No whole `pedantic`/`nursery`/`restriction` groups. Exceptions name the lint, use the narrowest scope and carry a reason. Tests may `unwrap`/`expect`; library code handling network input returns errors. | Strictness that works on the MSRV and stays reviewable; CI is never weakened to pass. |
| W-26 | 2026-09-20 | Fuzzing uses cargo-fuzz/libFuzzer on Linux x86-64 with AddressSanitizer in CI, from a dated nightly and a pinned cargo-fuzz version recorded once in `fuzz/toolchain.env`. Locally a distribution toolchain may run the same harnesses via `RUSTC_BOOTSTRAP=1` without a sanitizer; the wrapper prints the effective configuration. No root toolchain override; MSRV unchanged. | One configuration source for scripts and CI; honest reporting of what each run instrumented. |
| W-27 | 2026-09-20 | Every fuzz target has an independent oracle (reference grammar, layout decoder, hand-assembled bytes, or a state model written from the documented contract), not only crash detection and not a round trip through the same codec. Findings get a reproducer, a minimized input, an ordinary regression test on stable/MSRV and a `regression_*` seed. Panics are never caught and inputs never skipped to keep a campaign green. | An encoder and decoder can share a mistake; oracles must come from elsewhere. |
| W-28 | 2026-09-20 | Host adapters are tested deterministically through a narrow internal `Conn`/`Clock` seam with a scripted connection and virtual clock; the seam is `pub(crate)`, behind `std`, and is not a transport abstraction. Real-socket loopback tests remain the evidence for concurrency and cleanup. | Fault paths (short writes, `Interrupted`, trickle, EOF, `WriteZero`, deadline exhaustion) need exact timelines that sockets cannot provide; a public transport trait is still refused (C-07, W-06). |
| W-29 | 2026-09-20 | First TCP interoperability profile: `curve25519-sha256`, `ssh-ed25519`, `aes128-gcm@openssh.com` both directions, compression `none`, strict KEX offered under both `kex-strict-c-v00@openssh.com` and `kex-strict-c`, `ext-info-c` offered with `EXT_INFO` receive-only. Providers: `x25519-dalek` 2.0.1, `ed25519-dalek` 2.2.0, `sha2` 0.10.9, `aes-gcm` 0.10.3, `zeroize` 1.9, `subtle` 2.6, `base64ct` 1.8, `rand_core` 0.6 (injected), `getrandom` 0.2 (host only), behind `tatami_ssh_tcp/kex`, `tatami_ssh_keys/ed25519`, facade `kex`. | `crypto-provider-audit.md` records versions, features, MSRV (max 1.85 = workspace MSRV), no_std evidence and why each fits. Only implemented algorithms are advertised; the profile does not claim RFC 9142 MUSTs. Bare-metal build of the crypto features is a CI gate. |
| W-30 | 2026-09-20 | AEAD/MAC negotiation follows draft-miller-sshm-aes-gcm-01 §2 (as OpenSSH PROTOCOL §1.6 directs): AEAD names appear only in the cipher lists; when the selected cipher is an AEAD the MAC lists are ignored. Tatami's MAC lists carry `hmac-sha2-256` solely to satisfy RFC 4253's non-empty name-list syntax; no HMAC is implemented and negotiation fails closed (`NoMacImplemented`) if a non-AEAD cipher were ever selected, which our single-cipher proposal makes impossible. | Specified rather than guessed from the name; recorded as a compatibility gap in the inventory rather than hidden. |
| W-31 | 2026-09-20 | QUIC/TLS diagnostic backend: `quinn-proto` 0.11.18 (sans-I/O, no async runtime) with `rustls` 0.23.45 on `ring`, `rcgen` for ephemeral *test* identities, behind `tatami_ssh_quic/quinn-backend` which enables `std`; facade feature `quic-diag`; separate `tatami-quic-client`/`tatami-quic-server` binaries so TCP builds never pull the backend (binary split superseded by W-35; the feature boundary stands). ALPN is explicit and experimental (`tatami-diag/0` in examples), no registration or interoperability claim. 0-RTT disabled on both ends by building rustls configs directly (quinn-proto's convenience constructors enable early data). | Compiled evidence replaced the readiness note's candidate. This is a TLS/QUIC handshake observer; it sends no SSH bytes and settles no SSH-over-QUIC wire question. |
| W-32 | 2026-09-20 | Host trust for the active TCP client is an explicit operator-supplied `--host-key-sha256 SHA256:…` pin (OpenSSH-style SHA-256 of the complete public-key blob), applied by `tatami_ssh_keys::trust::PinnedSha256` through the `HostTrustPolicy` trait after the signature over the exchange hash verifies. A valid signature proves possession; the pin is the trust decision; both are reported separately and both gate `NEWKEYS`. No auto-enrollment, no `~/.ssh/known_hosts` reading. | Keeps mechanism (verification) and policy (trust) separate as C-03/§2.2 item 7 require; a known_hosts adapter can implement the same trait later (done in round 5, W-37; the pin remains an alternative, never combined with it). |
| W-33 | 2026-09-20 | `tatami-client handshake` is a short-lived initial-handshake diagnostic: it completes KEX, verifies signature and pin, exchanges protected packets, requests and receives `ssh-userauth`, sends a protected DISCONNECT and exits. It never sends `USERAUTH_REQUEST` (not even `none`), refuses a server rekey (`RekeyNotSupported`, then DISCONNECT), bounds protected packets (64), and never resets a nonce under the same key. Exit 0 only for `Completed`. | Full rekeying is required before general sessions; the diagnostic proves the transport milestone without pretending to be a client. |
| W-34 | 2026-09-20 | cargo-fuzz is installed with the **stable** toolchain and run under the pinned nightly. | cargo-fuzz 0.13.1's locked `rustix` 0.36.5 build script enables `rustc_layout_scalar_valid_range_*` attributes when it detects a nightly compiler, which 2026 nightlies reject (exit 101 in fuzz run 35544196809). cargo-fuzz inherits `RUSTUP_TOOLCHAIN` for the target builds, so building it on stable loses nothing. |
| W-35 | 2026-09-26 | One client and one server binary. The QUIC/TLS diagnostic is `tatami-client handshake --transport quic` and `tatami-server observe --transport quic`; `tatami-quic-client`/`tatami-quic-server` are removed. `--transport tcp\|quic` defaults to `tcp`, so TCP command lines are unchanged. Each transport keeps its own option set and defaults and rejects the other's options. QUIC stays behind `quic-diag` (with `tcp`, the binaries' required features); a build without it reports `--transport quic` as a usage error, mirroring `kex`. `probe` is TCP-only. | Operators want one tool per role rather than a binary per transport. The W-31 goal — TCP builds never pull `ring`/`rustls` — is kept by the feature gate, not by separate executables. This is command-line composition only; it introduces no transport abstraction (C-07, W-06), and the TCP and QUIC code paths remain separate. |
| W-36 | 2026-09-26 | The canonical host identity on every transport is the complete SSH public-key blob (`string("ssh-ed25519") \|\| string(key)`). TCP takes it from `K_S`; QUIC converts the peer's RFC 7250 SPKI to it with the one strict converter in `tatami_ssh_keys::spki` (OID 1.3.101.112, parameters absent, zero unused bits, 32-byte key validated by `ed25519-dalek`, minimal DER lengths, no trailing bytes; nothing else accepted). Both reach the same `HostTrustPolicy`; `known_hosts` compares complete blobs, not displayed fingerprints. The `SHA256:` fingerprint and the SSHFP value (4 2, SHA-256 of the blob) are derived from it. | Settles the P-06 mapping question for Ed25519: certificate DER, SPKI DER and blob hash differ, and only the blob matches what OpenSSH operators already pin and list. SSHFP is fingerprint *equivalence* for comparison with `ssh-keygen -r`, not DNS or DNSSEC trust. The QUIC backend's former prefix-only SPKI helper now delegates to the strict converter. |
| W-37 | 2026-09-26 | `known_hosts` support is a read-only, bounded, deliberately strict subset (`tatami_ssh_keys::known_hosts`, feature `known-hosts`): explicit file only; comments/blank lines; comma-separated patterns with `*`, `?`, `!` negation and `[host]:port`; `\|1\|salt\|hash` hashed names (HMAC-SHA1 via `hmac`/`sha1`, used for nothing else); `@revoked`; `@cert-authority` recorded but never trusted. The whole file is validated first: a malformed line, bad base64/blob, key-type mismatch or unknown marker (including in an `@revoked` line) is a configuration error with its line number. Limits: 1 MiB file, 16 KiB line, 10 000 entries, 256 patterns per line; glob matching is iterative and bounded. Decision over all applicable lines, in any order: applicable `@revoked` listing the key → `revoked`; applicable plain line listing it → trusted (rotation allowed); same-algorithm lines only for other keys → `key_changed`; only other algorithms → `no_key_for_algorithm`; only CA lines → `certificate_authority_only`; nothing → `unknown_host`. No prompt, enrollment or write; `~/.ssh` and system files are never read. | Stricter than OpenSSH (for example SSH-1 lines and unknown markers fail the file) so a broken revocation can never be skipped on the way to a positive match. Matching agrees with `ssh-keygen -F` on the tested plain and hashed queries. Supersedes the "no `known_hosts`" part of W-32. |
| W-38 | 2026-09-26 | The `known_hosts` lookup name is the host as typed, ASCII-lowercased, bare for port 22 and `[host]:port` otherwise, on both transports. It is bound before connecting; resolved addresses, `--server-name`/SNI and QUIC path changes never replace it, and the resolved address is not looked up in addition. Intended service convention: TCP 22 and UDP 22, which therefore share one entry; UDP 4433 stays the QUIC experiment's default port. | OpenSSH's rule (its client lowercases the name), so existing files work unchanged; same numeric port ⇒ same entry, different ports stay distinct. Keeping the logical identity separate from resolution leaves the hostname-resolution review free to change resolvers without changing trust. |
| W-39 | 2026-09-26 | OpenSSH host private keys are decoded by RustCrypto `ssh-key` 0.6.7 (`alloc` only; no `ed25519`, `encryption`, `std`, `ecdsa`, `rsa`, `dsa`), feature `tatami_ssh_keys/openssh-key`. Supported subset: unencrypted Ed25519 `openssh-key-v1`, at most 16 KiB. An encrypted key returns a specific error without any KDF (none is linked); there is no passphrase input. Tatami adds the seed→public derivation check that `ssh-key` skips without its `ed25519` feature. The PKCS#8 form (RFC 8410 §7) exists only in zeroizing memory and is loaded by the TLS provider from a borrowed buffer; no converted copy is written. Transient copies inside `ssh-key` and `ring` are outside Tatami's control. The facade reads the file bounded on the opened handle and, on Unix, refuses it if group/other bits are set; non-Unix platforms get no permission check. | A maintained parser rather than a new container implementation; its checks and gaps are listed in `crypto-provider-audit.md`. Encrypted keys, signing agents and HSMs are follow-on work, not silently approximated. |
| W-40 | 2026-09-26 | QUIC SSH host-key mode: `tatami-server observe --transport quic --host-key FILE` presents the key only as an RFC 7250 raw public key (asking for certificate presentation is a configuration error; `--host-key` excludes `--identity-dir`/`--generate-identity`). The client's `--known-hosts` / `--host-key-sha256` (SSH-blob fingerprint) require a raw public key and refuse a certificate peer; the verifier applies the preloaded shared policy (no file or DNS I/O) and still verifies TLS 1.3 `CertificateVerify` with the provider. The X.509 `--cert-sha256`/`--root-cert` modes are unchanged; exactly one trust option per run. | Proof of possession stays a provider signature check on each transport, never implied by a key match. A trusted host key over QUIC/TLS is **not** an SSH session: no SSH byte is sent and reports say `ssh_session: false`. |
| W-41 | 2026-09-26 | Trust-configuration errors are distinct from untrusted keys: an unreadable file, a malformed file or an unusable lookup name is detected before any connection and reported as `trust_configuration_error` (codes `io_error`, `malformed_configuration`, `invalid_lookup_name`); untrusted keys carry `UntrustedReason` codes after the key is seen. In JSON, on both transports, `trust_error` holds that stable code and `untrusted_reason` carries it too when no decision was made, so one field lists every structured trust-failure reason; the human message is in `outcome` (TCP) or `reason` (QUIC). Operator-supplied paths in these messages are escaped in text output. | A broken configuration must never look like "unknown host", and nothing is sent when the policy cannot be built. |
| W-42 | 2026-09-26 | SHA-1 is confined to OpenSSH hashed `known_hosts` names. The HMAC-SHA1 matcher moved from `tatami_ssh_keys` into the portable crate `tatami_ssh_openssh_compat` (`no_std`, `hmac`/`sha1` defaults off), whose only public items are `matches_hashed_hostname(stored_field, lookup_name) -> Result<bool, HashedHostnameError>` and that error (full `\|1\|salt\|hash` grammar, canonical padded base64, 20-byte salt/digest, bounded inputs, `verify_slice`; no writer, no digest/HMAC API, no re-exports). It is enabled only by `tatami_ssh_keys/openssh-hashed-hosts` (facade `openssh-hashed-hosts`), off by default and outside `kex`/`quic-diag`, and called only from `known_hosts.rs`. Without the feature any hashed entry, including `@revoked`/`@cert-authority`, fails the file as `KnownHostsError::Unsupported` (facade code `unsupported_configuration`, before connecting). `hash_hostname` was removed. `scripts/check-sha1-boundary.py` (self-tested, run by `check-workspace.sh`) checks the resolved facade graphs with the feature on (SHA-1 only via the compat crate) and off (neither reachable), allowed dependents/call sites and the public API; separate tests check that no SHA-1 SSH or TLS algorithm is enabled and that pins/SSHFP are SHA-256. | Supersedes the hashing part of W-37. Additive Cargo features cannot express "no SHA-1", so the disabled configuration is proven by inspecting its actual graph, not by `--all-features`. A hashed revocation that cannot be evaluated must not be skipped, hence an explicit error rather than ignoring the line. The claim is a dependency and configuration boundary: the bundled TLS backend (`ring`) may still contain SHA-1 code internally. |
| W-25 | 2026-09-20 | Accepted file-transfer direction (implementation deferred): SFTP v3 per `draft-ietf-secsh-filexfer-02` (an Internet-Draft, not an RFC) as the baseline, extensions only on demonstrated interoperability need; legacy SCP protocol out of scope (modern OpenSSH `scp` uses SFTP, a future acceptance target); experiment with one transfer per SSH channel per QUIC bidirectional stream within one authenticated connection, a separate metadata channel distinct from the transport control stream; confirm parent directories before each file, apply final directory timestamps/permissions after descendants, express cross-stream ordering as explicit successful-operation dependencies; bound concurrent files/memory/handles, measure per-file setup cost against a channel pool, never share session-scoped handles across sessions; benchmark ordinary/parallel SFTP over TCP and QUIC across sizes, latency and loss. | Recorded so later work starts from agreed constraints. Performance gain is a hypothesis; one stream per file is an experiment. No SFTP crate or wire change exists yet. |

## Package naming (W-42, 2026-09-27)

All Cargo packages and Rust crate identifiers use the `tatami_ssh` prefix.
The facade is `tatami_ssh`; the six supporting libraries are
`tatami_ssh_{wire,keys,auth,connection,tcp,quic}`. Their directories match
their package names. The isolated harness packages are
`tatami_ssh_fuzz_wire_core` and `tatami_ssh_fuzz_protocol`. This avoids using
the unrelated `tatami` package name. Dependency versions, features and
`publish = false` are unchanged. CLI names, SSH banners, experimental ALPN,
exporter labels and repository/branding names are unchanged.
